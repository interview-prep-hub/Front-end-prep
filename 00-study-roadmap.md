# 00. Study roadmap

Previous: [Index](README.md) | Next: [01. Resume map](01-resume-and-interview-scope.md)

## Goal and daily method

Prepare for front-end interviews grounded in your full-stack experience. Prioritize JavaScript, browser behavior, accessible CSS, React state/effects, API integration, and debugging. Study frameworks after those foundations so that you can explain their decisions rather than recite their APIs.

Default schedule: 12 weeks, six study days per week, about two hours per day. This is a suggested workload, not a promise of readiness. Shorten a topic only after passing its practical gate.

Use a two-hour session like this:

1. Recall yesterday's topic without notes for 10 minutes.
2. Read and explain one section for 25 minutes.
3. Implement a small feature or reproduce a bug for 50 minutes.
4. Answer questions aloud for 20 minutes.
5. Record a failure, correction, and next review date for 15 minutes.

Review a topic after roughly 1, 3, 7, and 14 days. Mix old questions into new sessions. Framework reading cannot replace hands-on JavaScript practice.

## Twelve-week sequence

| Week | Read | Build and pass |
| --- | --- | --- |
| 1 | 00-05 | Accessible, responsive housing listing without React |
| 2 | 06-09 | DOM search with cancellation, keyboard use, and explicit request states |
| 3 | 10-12 | Solve six coding problems; type an API boundary; scaffold a Vite app |
| 4 | 13-15 | React list with stable identity; fix stale closures and effect cleanup |
| 5 | 16-20 | URL filters, cached server data, validated form, API error handling |
| 6 | 21-24 | Interaction tests, a measured performance fix, threat review, SSR explanation |
| 7 | 25-27 | Next.js public detail page plus authorized mutation and cache policy |
| 8 | 28-30 | TanStack route/search validation, Start server function, tenant isolation |
| 9 | 31-35 | Explain Rails migration and Expo experience; complete one design round |
| 10 | 36-37 | Finish a focused capstone and two timed coding exercises |
| 11 | 38-40 | Prepare evidence-based project stories and run three mock rounds |
| 12 | 39-43 | Retest weak areas; run a full interview loop; final review |

For each week's sixth day, do an assessment instead of adding new content. Use the seventh day for rest or light recall.

## Four-week focused revision

Use this only if you already implement React features independently. Spend two to three hours per study day.

- Week 1: diagnose 01; revise 02-11; solve one language problem daily.
- Week 2: revise 12-24; build search, forms, and tests in Vite.
- Week 3: cover 25-30; build the same read/mutate feature in Next.js and Start; review 31-35 for resume follow-ups.
- Week 4: complete 36-40, make project stories precise, and use 41-43 to repeat weak topics.

If the language diagnostic is weak, use the thorough track. Skipping foundations usually shows up when an interviewer changes a requirement.

## Two-week intensive revision

Days 1-3: 02-11 with daily coding. Days 4-6: 13-23 and one machine-coding feature. Days 7-9: 24-30 with one framework comparison. Days 10-11: 31-38 and project evidence. Days 12-14: mocks, question bank, and targeted fixes. This is revision, not a first-time learning schedule.

## Priority when time is short

Core: 02-04, 06-08, 10-14, 16, 18-19, 21-26, 28-30, 36, 38, 40. Keep HTML/accessibility and security in the plan. Move specialized browser APIs and mobile depth later unless the job asks for them.

Stretch: complex type transformations, concurrent rendering internals, streaming/cache topology, offline conflict handling, micro-frontends, and large design systems. Be able to identify these topics before trying to master every implementation.

## Weekly assessment

Explain one concept in two minutes, implement one feature in 40 minutes, debug one seeded failure, and answer a tradeoff question. Record each score separately in 43. A strong explanation with weak code means the next session should be implementation; the reverse means it should be narration and reasoning.

Exit gate: choose a track, block study time, complete the diagnostic, and write the first three review dates.
